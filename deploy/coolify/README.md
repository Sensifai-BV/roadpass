# Deploying ROADPASS on Coolify

`docker-compose.coolify.yml` (repository root) is the whole stack for Coolify's
**Docker Compose** build pack: `app`, `worker`, PostgreSQL, ClickHouse, Redis,
OpenBao (signing keys), its one-shot initialiser, and the Hyperledger Fabric network.

Nothing is published on the host. Only Coolify's proxy is public; it reaches `app`
on port 8080 through the `SERVICE_URL_APP_8080` variable and issues the certificate.

## Set up

1. **New resource → Docker Compose** from this Git repository.
   *Base Directory* `/`, *Docker Compose Location* `/docker-compose.coolify.yml`.
2. Open the **app** service and give it your domain (`https://roadpass.example.com`).
   Coolify routes it to port 8080. `PUBLIC_URL` follows from it (invitation and reset links).
3. **Environment variables**
   | Variable | |
   |---|---|
   | `SIGNING_MASTER_KEY` | **required**: `openssl rand -hex 32`. Required at start-up. Back it up and never change it after the first deploy. |
   | `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM`, `SMTP_TLS` | optional; system e-mail. Can also be set later under Platform → Email delivery. |
   | `TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY` | optional; Cloudflare Turnstile on the public contact form. |

   Database passwords are generated by Coolify (`SERVICE_PASSWORD_POSTGRES`, `SERVICE_PASSWORD_CLICKHOUSE`).
4. **Deploy.** The first build compiles the dashboard, the Go binary and the Fabric image (several minutes).
5. **First run:** open the `app` service logs and find
   `first-run setup: no platform manager yet; open this link …`. Open that link (valid 24 h)
   to create the platform manager. A second setup is refused.

## Resource limits

ClickHouse and Fabric have CPU and memory limits (`deploy.resources`), set from environment variables so you can tune them in Coolify without editing the file:

| Variable | Default | |
|---|---|---|
| `CLICKHOUSE_CPUS` / `CLICKHOUSE_MEM_LIMIT` / `CLICKHOUSE_MEM_RESERVATION` | `2` / `4g` / `1g` | ClickHouse sizes its caches from the container limit; raise the limit for large datasets. |
| `FABRIC_CPUS` / `FABRIC_MEM_LIMIT` / `FABRIC_MEM_RESERVATION` | `2` / `2g` / `768m` | The one Fabric container holds the orderer, both peers and the chaincode. |
| `FABRIC_GOMEMLIMIT` | `1700MiB` | Keep it about 85% of `FABRIC_MEM_LIMIT` so the Go processes collect garbage before the OOM killer acts. |

## What runs

| Service | Notes |
|---|---|
| `app`, `worker` | One image, `serve` and `worker`. `ENVIRONMENT=production`, demo mode off. |
| `postgres`, `clickhouse`, `redis` | Internal only; state in named volumes. |
| `openbao`, `openbao-init` | Transit signing keys. `openbao-init` runs once per start (initialise, unseal, issue the app token) and exits; it is excluded from health checks. |
| `fabric` | Self-contained Fabric 2.5 network (orderer, two peers, chaincode). |

## Caveats

- **OpenBao unseal key:** `openbao-init` keeps the unseal key and root token in the `openbao-init` volume,
  as in the local stack. That is acceptable to start, not for a hardened production: move to auto-unseal
  (cloud KMS/HSM) and TLS on the OpenBao listener, and keep the root token offline.
- **Fabric:** the bundled network is a single-host network for the demonstrator. A production ledger
  joins your real Fabric network; that needs `FABRIC_*` settings rather than the `fabric` service.
- **Back up** the volumes `pg`, `ch`, `openbao-data`, `openbao-init`, `fabric-data`, `fabric-crypto`
  (Coolify → resource → Storages), together with `SIGNING_MASTER_KEY`.
- **Demo workspace:** `DEMO_TENANT=1` (the default here) creates the *Capital Paving* demo organisation on every start and rebuilds it daily
  (`docs/DEMO_WORKSPACE.md`: users `admin@capital-demo.com`, shared password `roadpass-demo-2026`; set `DEMO_TENANT_PASSWORD` to change it, `DEMO_TENANT=0` to turn it off).
  Set `TURNSTILE_SITE_KEY` and `TURNSTILE_SECRET_KEY` to put Cloudflare Turnstile on the sign-in and contact forms.
- **Simulated Spanish dataset** is not loaded. To try the product with a simulated chain, run
  `roadpass seed -reset -scale 0.3` in the `app` container's terminal (this wipes existing data).
- `exclude_from_hc` is a Coolify extension; plain `docker compose config` rejects it. To test the file
  locally, run it through `grep -v exclude_from_hc` first, with the variables above set.
